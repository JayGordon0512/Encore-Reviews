# Encore v1.5.0 — Invitation Scheduling Visibility

- Status: Implemented locally; sending remains disabled pending staging approval
- Date: 31 August 2026
- Scope: Encore organiser event management and held-invitation operations

## Release Notes

Organisers can see whether automatic review emails are active or paused and can
see customer, scheduled, sent, held, stopped and attention-required totals for
each event date. No attendee identity, email address or invitation token is
rendered in these summaries.

## Architecture Changes

None. Encore continues to own invitation scheduling and delivery. Ticketing
providers continue to own bookings, tickets and provider attendance evidence.

## Operational Changes

The new `encore:invitations:release-held-organiser` command gives operators an
explicit, bounded path for schedules created while organiser sending was off.
It is dry-run by default, refuses committed release while the organiser gate is
disabled, and creates an immutable audit record per released schedule.

Past-due schedules are released as due now. The existing scheduler batch limit,
identifier-only queue job and delivery-time authority checks remain effective.

## Breaking Changes

None.

## Migration Notes

No database migration is required.

## Known Issues

- Invitation sending remains disabled on staging until the controlled mail
  journey and operational monitoring are approved.
- Dead-letter recovery remains an operator action; organisers can see that an
  invitation needs attention but cannot retry delivery themselves.

## Deployment Notes

1. Deploy the web, scheduler and worker from the same revision.
2. Keep organiser and provider invitation gates disabled during smoke testing.
3. Verify the event page shows held totals without attendee data.
4. Run the held-release command without `--commit` and record the count.
5. Enable only the approved source gate across every runtime.
6. Release one bounded batch and monitor schedules, queue jobs, Mailgun delivery
   and dead letters before increasing the batch size.
7. Roll back by disabling the source gate. Already sent emails cannot be
   recalled; schedules not yet claimed remain safely undispatched.
