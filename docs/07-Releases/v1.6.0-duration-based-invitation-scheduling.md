# Encore v1.6.0 — Duration-Based Invitation Scheduling

- Status: Implemented locally; sending remains disabled pending staging approval
- Date: 1 September 2026
- Scope: Manual events and provider-backed invitation scheduling

## Release Notes

Invitation due times are now derived consistently from event start, event
duration and the configured post-event delay. Independent organisers select one
duration for an event and Encore calculates the end time for every performance.
The creation page previews both the calculated end and review-email time.

## Architecture Changes

Invitation timing is centralized in one application service shared by organiser
CSV attendance and provider eligibility. A provider-supplied end time remains
authoritative. If it is absent, Encore uses a configurable duration fallback.

## Operational Changes

`ENCORE_DEFAULT_EVENT_DURATION_MINUTES` controls the missing-end-time fallback
and defaults to 150 minutes. The source-specific post-event delay defaults to
one hour for both organiser and provider schedules.

## Breaking Changes

New manually created events must include a duration between 15 minutes and 24
hours. Existing events and existing invitation schedules are not rewritten.

## Migration Notes

No database migration is required. Manual-event duration is represented by the
persisted difference between `starts_at` and `ends_at`.

## Known Issues

- Provider performances without `ends_at` rely on the configured fallback.
- Existing held schedules retain the due time calculated when they were created.

## Deployment Notes

1. Deploy the web, scheduler and worker from the same revision.
2. Set the same duration fallback and source delays across all runtimes.
3. Keep invitation gates disabled during smoke testing.
4. Create a manual test event and verify its displayed end and planned review
   email time.
5. Import one test attendee and confirm its schedule matches the displayed time.
