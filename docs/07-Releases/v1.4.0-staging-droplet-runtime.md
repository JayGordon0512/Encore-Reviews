# v1.4.0 — Staging Droplet runtime

## Status

Implementation complete locally. Droplet creation, deployment, DNS cutover and
App Platform archival require separate operational evidence before this release
is marked deployed.

## Purpose

Move Encore staging from per-component App Platform operation to a dedicated,
containerised Droplet runtime consistent with the established TicketPal staging
operating model. Encore retains its own server boundary, private PostgreSQL
database volume, Spaces artwork and backup storage, and independent
configuration.

## Runtime topology

- host Nginx terminates public ingress and proxies only to `127.0.0.1:8081`;
- an Nginx container serves public assets and forwards the Laravel entry point
  to PHP-FPM;
- a dedicated PHP-FPM application container handles web requests;
- a dedicated database-queue worker consumes only the `invitations` queue;
- a dedicated scheduler container runs Laravel's scheduler continuously;
- PostgreSQL 17 runs on the private Compose network with a persistent volume and
  no published database port;
- a daily verified PostgreSQL dump is uploaded to the private Spaces bucket.

## Security and activation controls

- the populated runtime environment remains root-only on the Droplet;
- only SSH, HTTP and HTTPS require public firewall access;
- deployment uses an argument-free, root-owned wrapper with an exclusive lock,
  clean-checkout enforcement and immutable revision-tagged images;
- provider and organiser invitation issuing remain disabled during migration;
- database backups are root-run, lock-protected and locally retained for seven
  days after successful Spaces upload;
- no TicketPal application or infrastructure change is included.

## Verification completed

- deployment wrapper shell syntax check;
- Docker Compose configuration validation;
- four staging architecture tests with nineteen assertions;
- full PHPUnit suite: 80 tests, 892 assertions, with the existing missing local
  `.env` warnings;
- Pint validation across 144 PHP files;
- production Vite build.

## Deployment order

1. Create the dedicated Ubuntu 24.04 LTS Droplet in LON1.
2. Harden the host and install Docker, host Nginx and Certbot.
3. install repository access, the root-only environment and deployment wrapper.
4. start the private PostgreSQL service and restore a verified App Platform
   database dump.
5. compare source and destination data, then deploy `main`.
6. verify the application, worker, scheduler and an initial Spaces backup.
7. switch staging DNS and issue the TLS certificate.
8. monitor and run controlled invitation tests with issuing still disabled.
9. archive App Platform and remove its development database only after rollback
   is no longer required; never destroy Spaces data.

## Rollback

Before App Platform archival, restore the staging DNS record to the existing
App Platform target. Until the App Platform database is removed, it remains the
source rollback database. After removal, restore the latest verified custom
format dump from Spaces into the Droplet PostgreSQL volume.
