# Encore v1.1.0 — Invitation Delivery Foundation

Encore exists to orchestrate the live entertainment ecosystem through trusted experiences and collective intelligence.

- Status: Implemented locally; activation prohibited pending operated-worker and mail verification
- Date: 27 August 2026
- Governing decisions: ADR-017 and ADR-018 (both remain Proposed)

## Release outcome

Encore can convert a due, consented Provider API v2 eligibility schedule into
one Encore-owned review invitation and deliver a branded email through an
identifier-only background job. The provider does not receive, store or send
the invitation capability.

## Security and privacy controls

- New tokens contain at least 128 bits of entropy and are stored only as keyed,
  versioned HMAC digests.
- Legacy SHA-256 invitation lookup remains available for the bounded migration
  window; new writes use token version 2.
- The queue job contains only the invitation schedule UUID.
- Email, display name and plaintext token are prohibited from jobs, outbox,
  delivery evidence, audit records and failed-job payloads.
- Review invitation pages send `Referrer-Policy: no-referrer` and
  `X-Robots-Tag: noindex, nofollow` headers and matching document metadata.
- A failed delivery revokes the undelivered token. A retry generates a new
  capability rather than storing recoverable plaintext.
- Consent withdrawal revokes any issued, unredeemed v2 invitation and cancels
  its schedule.

## Operational behavior

- `encore:invitations:dispatch-due` finds due or stale schedules and dispatches
  identifier-only jobs to the `invitations` queue.
- The scheduler runs the dispatcher every minute.
- Attempts are bounded and use explicit retry availability. Exhausted work
  enters `dead_lettered` schedule state with a safe error code.
- Delivery attempts have first-class token-free state in
  `review_invitation_deliveries`.
- Duplicate jobs and stale claims produce at most one active invitation.

## Activation gates

Do not set `ENCORE_PROVIDER_V2_INVITATION_ISSUING_ENABLED=true` until all of the
following are evidenced in the target environment:

1. a supervised scheduler process is running;
2. a supervised `invitations` queue worker is running;
3. TicketPal's approved email delivery provider is configured for Encore with
   an Encore-specific verified sender identity and separately rotatable
   credentials;
4. the token digest and contact fingerprint keys are securely configured;
5. queue backlog, failed jobs and dead-letter schedules have monitoring and an
   operational owner;
6. a controlled staging eligibility produces one email and one redeemable link;
7. a simulated mail outage recovers without duplicate usable links.
8. invitation-token query strings are redacted from edge/application access
   logs, or the review entry flow is replaced by a fragment/token-exchange
   design that keeps the capability out of request URLs.

Provider v2 ingress and invitation issuing remain independently controlled.
This release does not authorize production activation or change the legacy
TicketPal invitation endpoint.

## Known issue

The current review form accepts the invitation capability in the query string.
The page prevents referrer and crawler leakage, but infrastructure access-log
redaction has not yet been proven. Invitation issuing must remain disabled until
that evidence exists or the entry flow no longer transmits the token in a URL.

## Verification

Feature coverage proves due dispatch, successful delivery, keyed-token
redemption, duplicate suppression, disabled-state safety, token-free persisted
operational evidence, delivery failure revocation and replacement-token retry.
The full PostgreSQL release suite remains the merge/deployment gate.
