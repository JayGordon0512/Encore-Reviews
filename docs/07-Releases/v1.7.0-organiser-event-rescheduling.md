# Encore v1.7.0 — Organiser Event Rescheduling

- Status: Implemented locally; sending remains disabled pending staging approval
- Date: 6 September 2026
- Scope: Independent organiser event management and invitation safety

## Release Notes

Independent organisers can edit event details, venue, duration and active
performance start times, or add further dates. They can cancel individual
performance dates from the event management page. Changes remain tenant scoped
and are recorded in the administrative audit log.

Timing changes recalculate only unsent invitation schedules. Cancellation
withdraws pending schedules and revokes unused invitation links. Cancelled dates
remain visible to the organiser as history, but are removed from the public
event page and cannot receive new customer imports.

## Architecture Changes

No architectural baseline changes. Event mutation remains within the modular
application service boundary and uses the existing invitation scheduling,
tenant authorization and audit controls.

## Operational Changes

Operators should treat a cancelled performance as terminal. An email already
accepted by the mail provider cannot be recalled, but its unused Encore link is
revoked. Scheduled and disabled-held organiser invitations are recalculated when
timing changes; sent, dead-lettered and other terminal records are not rewritten.

## Breaking Changes

None. Provider-backed TicketPal events cannot use the manual event-management
routes, and the Provider API v2 contract is unchanged.

## Migration Notes

No schema or data migration is required.

## Known Issues

- Event duration is shared across every active date in a manually managed event.
- Cancelling a date does not delete its historic attendance, invitation or audit
  records.
- Invitation delivery remains disabled until the existing staging activation
  gates are approved.

## Deployment Notes

1. Deploy web, scheduler and invitation worker processes from the same revision.
2. Keep organiser and provider invitation issuing disabled during smoke tests.
3. Create a manual test event with two dates and import one test attendee.
4. Change the imported date's start time and duration; verify the held schedule
   matches the new performance end plus the configured one-hour delay.
5. Cancel that date; verify its schedule and unused link are withdrawn, it is
   absent publicly, and further CSV imports for it are rejected.
6. Confirm the create, update and cancellation audit records contain no customer
   contact data.
7. Roll back the application revision if required. The release adds no schema;
   event changes already made by organisers are durable business data and must
   not be reverted automatically.
